# 智价台 · 词元经济行情与智能服务交易仿真

## 项目概述
- **名称**：智价台（webapp）
- **目标**：按《词元经济行情与智能服务交易平台 战略深化方案 V2.0》搭一套可以实际操作的前端仿真环境，演示"一图谱、三行情、双路径、一仿真"的产品形态。
- **定位**：产品概念演示。模型、服务商与报价用真实公开数据；成交、盘口、历史走势是合成数据，界面上逐处标注。

## 数据架构
- **真实数据**（快照 2026-11-17 09:56 北京时间）：470 个模型（443 个精确版本、19 个别名、8 个路由）、61 个品牌、80 家算力中心、1003 条公开报价、463 个可比桶。来源为 OpenRouter 公开目录 API，汇率来自 open.er-api.com。
- **真实调价记录**：`public/static/data/history.json`。每运行一次 `npm run snapshot`，就把新旧两份端点快照逐个端点比较并追加一个观测区间。目前 1 个区间（2026-11-17 02:40 → 2026-11-17 09:56）：比较 1520 个端点，55 个调价（上调 41、下调 14）。
- **合成数据**：成交价、K线、交付量、盘口、逐笔、报价历史、指数、任务合格率、逐日涨跌。全部由桶 ID 与日期做种子，可逐位复算。
- **数据流**：`scripts/snapshot.mjs` 生成离线快照 → 浏览器加载快照并构建可比桶 → 后台经 Worker 代理刷新实时目录；上游不可达时回退快照并显示快照时间。
- **存储**：无服务端存储。仿真账户（`zjt.account.v1`）、入场状态与存证链（`zjt.access.v1`）、目录默认标价的逐日观测（`zjt.obs.v1`）都保存在浏览器 localStorage。
- **归一口径**：`public/static/js/core/normalize.js` 一份实现，Worker、快照脚本、浏览器三处共用。

## 行情规则（对应方案章节，均有单测）
- 固定篮子参考价 = 80% 输入 + 20% 输出（§06）
- 无样本的交易日留空，不复制前收；单样本时开高低收相同（§07）
- 发布门槛：≥3 家独立供应主体、≥5 个独立买方、≥10 笔样本（§08）。463 个桶中 107 个供应商数达标，其余只显示报价、不开放撮合
- 日均样本 ≥60 笔才提供日内粒度，目前 38 个桶（§07）
- 指数：固定基期 = 100，等品牌组权重，缺失超 5 天剔除（§08）
- 盘中聚合到收盘 = 该日日线；换日后历史不变（§11 可重放）

## 入场与审批（拟议流程的仿真）
- 依据广东公开确立的"无场景不登记、无登记不交易、无合规不上架"与合规会审机制（来源：国家发展改革委网站 2022-11-01 文章）。
- 环节、材料、时限是我方设想，**不是广州数据交易所的实际业务规则**；演示里由使用者自己扮演审核方，检查项不合格时系统不允许通过。
- 未入场不能下单、不能签约；用途选"额度转售""囤积等待升值"，或涉及个人信息、数据出境而未完成评估，会卡在合规会审。
- 供给方上架预检用公开目录的真实数据：推理精度已声明、状态正常、近1日可用率 ≥95%、机房所在地已披露，四项都过才能登记。
- 存证链：SHA-256，每条包含上一条的哈希，可校验、可演示篡改被发现。只存在本机浏览器，无第三方见证，不具备法律存证效力。
- 所有编号带 `SIM-` 前缀，不是真实登记凭证。

## 使用说明
0. 先到"入场"：点"填入演示数据"→"提交申请"→ 逐环节通过（或"一键走完后续环节"）。未入场不能下单和签约。
1. 打开"行情"，点任意一行进入交易终端。
2. 在右侧下单：限价单可点盘口价格带入；市价单只吃可见盘口。期初研究记分 100,000。
3. 图表上方切换"成交K线 / 报价视图 / 任务成本"，下方行情卡说明当前口径。
4. 到"采购台"发起询价，签约后模拟一个账期履约，核对账单再验收结算。
5. "资产"页查看账务勾稽，可重置仿真账户。
